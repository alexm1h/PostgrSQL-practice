# Лабораторные работы по курсу «Базы данных» (PostgreSQL)

Данный репозиторий содержит выполненные лабораторные работы по дисциплине «Базы данных». Работы выполнялись с использованием реляционной СУБД **PostgreSQL** и демонстрационной базы данных об авиаперевозках (demo database), которая разворачивалась локально. В качестве клиента использовалась среда **DBeaver**.

**Выполнили:** Михайлов А.О., Шарапов Г.А., Саночкин Р. (гр. 4313)

---

## 📂 Структура репозитория

*   `lab1_join.sql` — Лабораторная работа №1. Выборка данных, агрегация и JOIN.
*   `lab2_check.sql` — Лабораторная работа №2. Обеспечение целостности данных.
*   `transactions/` — Лабораторная работа №3. Транзакции, блокировки и триггеры.

---

## 📝 Краткое описание работ

### Лабораторная работа №1: Основы SQL и соединения таблиц
**Файл:** `lab1_join.sql`

В ходе работы были освоены базовые и продвинутые операции извлечения и модификации данных:
*   Команды `SELECT`, `INSERT`, `UPDATE`, `DELETE`.
*   Сортировка (`ORDER BY`), фильтрация (`WHERE`, `IN`, `BETWEEN`).
*   Агрегация данных (`GROUP BY`, `HAVING`, `ROLLUP`, `GROUPING`) и объединение (`UNION`).
*   Работа со строками: конкатенация (`||`), разбиение строк (`SUBSTRING`, `LENGTH`, `CASE`).
*   Изучение различных типов соединений таблиц: `INNER JOIN`, `LEFT JOIN`, `RIGHT JOIN`.
*   Работа с массивами (`ARRAY_POSITION`).

### Лабораторная работа №2: Обеспечение целостности данных
**Файл:** `lab2_check.sql`

Работа посвящена проектированию схем и защите данных от некорректного ввода:
*   Создание таблиц с ограничениями (`CREATE TABLE`).
*   Использование ограничений: `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK`.
*   Настройка поведения внешних ключей при удалении: `CASCADE`, `RESTRICT`, `SET NULL`.
*   Изменение структуры существующих таблиц (`ALTER TABLE`).
*   Работа с системными каталогами (`information_schema.columns`, `pg_constraint`).
*   Замена проверок через `LIKE` на более строгие регулярные выражения (`~`).

### Лабораторная работа №3: Транзакции, блокировки и триггеры
**Папка:** `transactions/`

Изучение параллельного доступа к данным и автоматизации на уровне СУБД:
*   Исследование уровней изоляции транзакций: `READ COMMITTED`, `REPEATABLE READ`, `SERIALIZABLE`.
*   Воспроизведение аномалий параллельного доступа и ошибок сериализации.
*   Использование пессимистичных блокировок строк (`FOR UPDATE`) и параметра `lock_timeout`.
*   Создание триггеров на языке `PL/pgSQL`:
    *   Триггер аудита (логирование `INSERT`, `UPDATE`, `DELETE` в формате `JSONB`).
    *   Запрещающий триггер `BEFORE DELETE`, блокирующий удаление капитана при наличии у него рейсов.

## 🛠 Требования для запуска

Для воспроизведения кода вам понадобятся:
1.  Установленный **PostgreSQL** (версия 14+).
2.  Клиент для работы с БД (например, **DBeaver**).
3.  Развернутая демонстрационная база данных `demo` (доступна на сайте Postgres Pro).

## 🚀 Как запустить
Каждый скрипт можно выполнять последовательно в SQL-редакторе. 
*Замечание для ЛР №3:* Так как третья работа включает тесты с транзакциями, для ее проверки необходимо открыть две сессии (две вкладки) в вашем SQL-клиенте для имитации параллельного доступа пользователей.
